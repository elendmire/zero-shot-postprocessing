## Rule of thumb for citing a breakpoint number

- **Pooled EMOS CRPS/coverage breakpoint (all leads)** → `phase3_low_n_grid_breakpoints.parquet`, never `phase3_data_size_sweep_breakpoints.parquet`.
- **DRN or variance-inflation-trainfit breakpoint** → `phase3_data_size_sweep_breakpoints.parquet` (the only source; not re-tested at low N).
- **Any lead-time-bucketed (0-24h/24-72h/72-120h) breakpoint** → `phase3_lead_time_bucketed_breakpoints.parquet`. As of fix-round-1 (Blocking Fix 1) it IS re-tested down to k=1, the same extended grid `phase3_low_n_grid_breakpoints.parquet`/F1 use — no longer a caveat.
- **"Does TimesFM-3 uniquely win at short lead, or does variance-inflation also beat it there?"** → `phase3_short_lead_variance_inflation_check.parquet` (new this fix round), not an inference from the all-leads `phase3_data_size_sweep.parquet` table, which does not break out variance-inflation by lead-time bucket at all.

## CRPS estimator consistency check (04_results.tex review, D5)

Table 2's full-N CRPS numbers for EMOS pooled (1.2612 K), raw ensemble
(1.3590 K), and TimesFM-3 (1.3592 K) — read from
`phase3_data_size_sweep.parquet`'s "full" row (Section 2.3's B1 pinball-loss
CRPS estimator, `crps_from_quantiles`, applied identically to every method) —
were checked directly against the same three methods' CRPS in
`phase3_summary_metrics.parquet` (an earlier, independent run, predating the
N-sweep grid): 1.261212, 1.359007, 1.359170 respectively. These round to the
same 4-decimal values Table 2 reports. **The estimator was already
consistent before and after Section 2.3's wording fix; the fix changed only
how the estimator's use was described in prose, not any computed number.**
This is not a "bug found and fixed" — it is a direct verification that no
such bug existed, run because the review asked whether it might have.
