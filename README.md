# Zero-shot time series foundation models for statistical postprocessing

Code and analysis for the paper *"Zero-shot time series foundation models
for statistical postprocessing of weather forecasts: how much training data
do they replace?"* (Ömer Faruk Avcı, İTÜ, 2026). We compare a frozen,
zero-shot TimesFM-3 against trained EMOS/DRN postprocessing baselines on
EUPPBench, and measure the training-data size at which the trained methods
catch up to and overtake the zero-shot model.

## Headline findings

| Question | Answer |
|---|---|
| Does zero-shot TimesFM-3 beat trained postprocessing on CRPS at full training data? | No. Every trained method (EMOS pooled 1.2612 K, EMOS local, DRN) beats TimesFM-3 (1.3592 K), and so does a one-parameter variance-inflation rescaling that uses no training data at all. |
| How much training data closes that gap? | Roughly 10 calendar days (day-blocked significance; the raw point-estimate crossing is earlier, ~6 days, but is not itself statistically significant). |
| Does TimesFM-3 have any real, settled advantage? | Yes — calibration-sharpness. Even a leakage-optimistic trivial rescaling (fit directly on test-set coverage, an upper bound no legitimate method could beat) still needs a wider interval, by 0.3965 K (95% CI [0.2887, 0.4997], day-blocked bootstrap). |
| Does supplying TimesFM-3 with ensemble spread as a second covariate close that gap? | No. It worsens CRPS (1.3592 → 1.3837 K) and only reaches near-nominal coverage at a substantially wider interval — a shift along the calibration-sharpness trade-off, not a clean win. |

Every number above (and every number in the paper) is generated by
`scripts/generate_numbers.py` from the `results/*.parquet` files in this
repo — never hand-typed. See `paper/main.tex` for the full argument and
`docs/results_index.md` for what each results file contains.

**Scope.** This evidence is for one time series foundation model,
TimesFM-3; whether it generalizes to other pretrained time series models
(e.g. Chronos-2, Moirai-2) is untested. The findings are also specific to
the target variable studied here, 2 m temperature, where EMOS's Gaussian
predictive family is close to ideally specified — for targets requiring
non-Gaussian or target-specific reformulations, a trained method's
small-sample advantage should not be assumed to appear as early.

## Repository layout

```
src/zeropp/       Library code: data loading/QC, models (EMOS/DRN/TimesFM-3/
                  variance-inflation), evaluation (scores, calibration,
                  significance testing), results provenance.
scripts/          Numbered analysis scripts, run in order (see below) to
                  reproduce every results/ file and every figure.
configs/          Quantile levels, training-data-size grid, seeds.
results/          Small aggregate result files (parquet + json provenance
                  sidecar per file: git SHA, model version, config hash).
                  These are what scripts/generate_numbers.py reads.
figures/          Generated figures (SVG/PDF vector sources committed; PNG
                  previews are not).
paper/            The manuscript itself (LaTeX source + generated_numbers.tex
                  + a pre-built main.pdf).
docs/             Data/results schema references, figure style guide.
tests/            pytest suite — runs without any real data or GPU (uses
                  small synthetic fixtures).
```

## Setup

Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
# or: pip install -e ".[dev]"   (uses pyproject.toml)
```

This installs everything needed to run the test suite, regenerate figures
from existing `results/` files, and rebuild the manuscript's numbers and
PDF. It does **not** install `timesfm` — that's only needed to actually run
TimesFM-3 inference (see below), and is heavier (GPU-oriented) than the
rest of the stack.

## Test suite

```bash
pytest tests/ -q --ignore=tests/test_tsfm_timesfm.py \
  --ignore=tests/test_tsfm_timesfm_mean_only_regression.py
```

164 tests, synthetic fixtures only, no data or GPU required, runs in a few
seconds. The two ignored files need the real `timesfm` package and real
model weights loaded; they're excluded from the default run for that reason,
not because they're unreliable.

## Data

This project uses [EUPPBench v1.0](https://doi.org/10.5281/zenodo.7429236)
(Demaeyer et al. 2023), restricted to its German subset (49 stations, 2 m
temperature). EUPPBench's own train/test split is used unmodified.

**Data acquisition is currently a manual step** — every analysis script in
this repo loads the data directly via `zeropp.data.build`/`zeropp.data.splits`;
there is no download/build orchestration script. To reproduce:

1. Obtain EUPPBench's German t2m subset (via the
   [climetlab-eumetnet-postprocessing-benchmark](https://github.com/EUPP-benchmark/climetlab-eumetnet-postprocessing-benchmark)
   package, or directly from the Zenodo record above).
2. Place four NetCDF files under `data/raw/` with these exact names
   (`zeropp.data.build`'s functions expect them):
   - `data/raw/germany_ensemble_reforecasts_t2m.nc`
   - `data/raw/germany_reforecasts_observations_t2m.nc`
   - `data/raw/germany_ensemble_forecasts_t2m.nc`
   - `data/raw/germany_forecasts_observations_t2m.nc`

`data/` is gitignored; nothing under it is or should be committed.

## Reproducing the results

Scripts are numbered by run order (01–16), with two exceptions that must
run first regardless of number: `01_run_baselines.py` needs no GPU and can
run anytime; `02_run_tsfm.py` needs a GPU and produces
`results/phase2_comparison_raw.parquet`, which every script numbered 03
and above reads. All scripts assume `data/raw/` is populated (see above)
and are run from the repo root.

**Step 1 — CPU-only, no GPU needed:**

```bash
python scripts/01_run_baselines.py   # raw ensemble, EMOS, DRN, variance-inflation
```

**Step 2 — needs a GPU and the real `timesfm==3.0.1` package + TimesFM-3
weights** (`google/timesfm-3.0-pytorch`, distributed under the TimesFM
Non-Commercial License v1.0 — see `LICENSE`):

```bash
python scripts/02_run_tsfm.py   # ~2-3 hours on a single A100
```

`results/phase2_comparison_raw.parquet` (this script's output) is the one
large intermediate file in this project (~122 MB) — it is gitignored and
not part of this repo. If you only want to reproduce the trained-baseline
results (not re-run TimesFM-3 inference), the small aggregate
`results/*.parquet` files already in this repo are sufficient and you can
skip straight to Step 4.

**Step 3 — needs a GPU too** (a second, smaller TimesFM-3 run supplying
ensemble spread as an extra covariate):

```bash
python scripts/13_two_covariate_timesfm_check.py   # ~2 hours on a single A100
```

**Step 4 — CPU-only, no GPU needed** (reads `phase2_comparison_raw.parquet`
from Step 2; each runs in seconds to a few minutes, except
`03_data_size_sweep.py`, which fits many EMOS models across the full
N-grid and both sampling arms — a few minutes):

```bash
python scripts/03_data_size_sweep.py
python scripts/04_summarize_results.py
python scripts/05_lead_time_breakdown.py
python scripts/06_lead_time_grouped_analysis.py
python scripts/07_spatial_block_significance.py
python scripts/08_compute_pit_histograms.py
python scripts/09_persistence_augmented_emos.py
python scripts/10_per_lead_group_significance.py
python scripts/11_lead0_contamination_check.py
python scripts/12_breakpoint_significance_sweep.py
python scripts/14_ensemble_subsample_check.py
python scripts/15_leaky_width_uncertainty.py
python scripts/16_leaky_lambda_at_two_covariate_coverage.py
```

**After all of the above:**

```bash
python scripts/generate_numbers.py   # writes paper/generated_numbers.tex from results/
python scripts/make_figures.py       # writes figures/*.{svg,pdf,png}
python scripts/check_references.py   # validates every \citep/\citet against refs.bib
cd paper && latexmk -pdf main.tex    # rebuilds the manuscript PDF
```

## Provenance

Every `results/*.parquet` file has a `.json` sidecar recording the git SHA,
a model/method version string, and a hash of the config used to produce it
(`src/zeropp/eval/results.py`'s `write_result`). See `docs/results_index.md`
for what each file contains and which script produces it.
